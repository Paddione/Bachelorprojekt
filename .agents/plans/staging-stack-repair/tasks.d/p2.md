# P2 — Fehlende Migrations auf staging shared-db

Ziel: error_log + admin_actions existieren in staging shared-db (Website-DB); tickets.tickets verifizieren.
budget_tokens: 60000 (min_tier 27b-local)

Konzept (RC2): migrate.ts (runMigrations) wird NUR standalone aufgerufen (tsx src/db/migrate.ts) — nicht beim App-Start. Idempotent, tracks schema_migrations, toleriert ALREADY_EXISTS (SQLSTATE 42P07/42710/42701). tickets.tickets wird beim App-Boot von tickets-db.ts angelegt.
Dateien (lesen aus Worktree, kein Write):
- components/website/src/db/migrations/20260703_create_error_log.sql
- components/website/src/db/migrations/20260525_admin_actions.sql
- components/website/src/db/migrate.ts

Steps:
1. Website-Pod in workspace-staging finden (kubectl -n workspace-staging get pods).
2. Preferiert: `kubectl -n workspace-staging exec <pod> -- tsx src/db/migrate.ts` (aus dem App-Verzeichnis). Fallback: psql via shared-db-Pod (Credentials aus Pod-Env/DSN; beide SQLs anwenden).
3. Verifizieren: psql `-c "SELECT table_name FROM information_schema.tables WHERE table_name IN ('error_log','admin_actions','tickets')"` → 3 Zeilen.
4. Falls tickets.tickets fehlt: Website-Deployment neu starten (App-Boot legt sie an) und Schritt 3 wiederholen.

Done when: 3-Tabellen-Check grün (exit 0).
Stop when: kein Pod/tsx/psql; DB-Auth-Fehler nach 2 Versuchen.
Rejected: Pod-Neustart als alleiniger Migrations-Trigger; Repo-Edits (out of scope).
