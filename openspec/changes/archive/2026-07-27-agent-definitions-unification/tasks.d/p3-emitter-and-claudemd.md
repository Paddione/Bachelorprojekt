## Aufgaben

- [ ] **P3.1 — T002308: `atomicWriteFile()`-Fehlerpfad reparieren.** Aktueller Code:

```js
} catch (err) {
  // Best-effort cleanup of the tmp on failure; ignore ENOENT (already gone).
  try { await rename(tmp, dest); } catch { /* ignore */ }
  throw err;
}
```

      Der Kommentar kündigt ein Aufräumen an, der Code wiederholt aber exakt die
      `rename(tmp, dest)`, die im `try` gerade fehlgeschlagen ist. Ersetzen durch `unlink(tmp)`,
      `ENOENT` weiterhin schlucken, den Originalfehler unverändert weiterwerfen. `unlink` aus
      `node:fs/promises` importieren.

      Beweis für den Fehler liegt im Verzeichnis — drei verwaiste Dateien aus früheren Abbrüchen:

```bash
ls -1 docs/agent-guide/maps/*.tmp 2>/dev/null || echo "(keine)"
```

      Diese drei sind gitignored und werden im Zuge des Fixes entfernt.

      inklusive des `HEADER`-Konstanten-Banners („DO NOT EDIT — generated by …"). Zwei Tabellen,

      - **Rollen:** Agent, Zuständigkeit, Claude Code, agy, opencode, Tools.
      - **Runtimes:** Agent, Modus, Modell, schreibfähig, Hinweis.

      Aussage „geladen, aber Modellfeld wirkungslos" ist genau die, die verlorenginge.
