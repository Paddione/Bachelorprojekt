## MODIFIED Requirements

### Requirement: Docs-Content-Linting auf veraltete und verbotene Inhalte

The system SHALL reject stale cluster-topology wording (`korczewski-Cluster`,
`separater Cluster`, `separates Cluster`) in the actively maintained top-level
documents `docs/*.md`.

The corpus is deliberately narrow. Frozen snapshots under `docs/legacy-html/`,
audit evidence, plan archives and third-party plugin documentation are
historical records: they are allowed — and often required — to name the
pre-consolidation topology.

The previous blanket ban on the service names `Mattermost`, `InvoiceNinja` and
`Stripe` is withdrawn. It was written for a small hand-curated docsify corpus
under `k3d/docs-content`. The docs are now generated by
`scripts/build-docs.mjs`, which aggregates `docs/**/*.md`, frozen HTML
snapshots, repo and plugin skill definitions and agent definitions into
`k3d/docs-content-built/`. In that corpus each of the three names occurs
legitimately: `stripe_invoice_id` is a live column in the rendered schema
diagram, third-party plugin documentation mentions Stripe, and
`contributing.html` names Mattermost and InvoiceNinja precisely to record that
they were decommissioned. A substring blacklist cannot separate a stale claim
from a historical record, so it produces only false positives.

#### Scenario: Veraltete Cluster-Topologie-Bezeichnung in gepflegten Dokumenten

- **GIVEN** eine Datei `docs/<name>.md` auf oberster Ebene enthält
  `korczewski-Cluster`, `separater Cluster` oder `separates Cluster`
- **WHEN** der Docs-Content-Guard läuft
- **THEN** schlägt er fehl und nennt den Dateipfad

#### Scenario: Historische Aufzeichnungen bleiben unangetastet

- **GIVEN** `docs/legacy-html/architecture.html` enthält in einem eingefrorenen
  Mermaid-Schnappschuss den Text `korczewski-Cluster`
- **WHEN** der Docs-Content-Guard läuft
- **THEN** ist der Guard grün — der Korpus umfasst nur `docs/*.md`

#### Scenario: Der Guard prüft einen nicht-leeren Korpus

- **GIVEN** der Guard scannt `docs/*.md`
- **WHEN** die Anzahl der gefundenen Dateien gemessen wird
- **THEN** ist sie größer als null, bevor die Negativ-Aussage ausgewertet wird —
  ein leerer Korpus darf den Guard nicht vakuos grün werden lassen

### Requirement: Docs-Content-Vollständigkeit — Mermaid-Diagramme und Glossar

The system SHALL ensure that every service page in the built docs under
`k3d/docs-content-built/` carries at least one Mermaid diagram, and that
`glossary.html` and `decisions.html` are both shipped with substantive content.

`keycloak` is no longer part of the service-page list: Pocket ID replaced
Keycloak as the OIDC provider and no `keycloak` page is generated any more.

#### Scenario: Jede Service-Seite enthält mindestens ein Mermaid-Diagramm

- **GIVEN** die gebauten Seiten `nextcloud`, `collabora`, `talk-hpb`,
  `livestream`, `einvoice`, `claude-code`, `vaultwarden`, `website`,
  `whiteboard`, `mailpit`, `monitoring` und `shared-db` unter
  `k3d/docs-content-built/`
- **WHEN** jede Datei auf Mermaid-Markup geprüft wird
- **THEN** enthält jede Seite mindestens einen Treffer — fehlt er, schlägt der
  Guard fehl und nennt die Seite

#### Scenario: Glossar und Decisions sind nicht-trivial befüllt

- **GIVEN** `k3d/docs-content-built/glossary.html` und
  `k3d/docs-content-built/decisions.html`
- **WHEN** der Textinhalt beider Dateien ohne HTML-Tags gezählt wird
- **THEN** enthält jede Datei mehr als 300 Wörter

## REMOVED Requirements

### Requirement: Docs-Sidebar-Integrität und Brand-Switch-Shell

**Reason:** Beide geprüften Artefakte existieren nicht mehr.
`k3d/docs-content/_sidebar.md` war die handgepflegte Docsify-Sidebar; die
Navigation wird heute von `scripts/docs-gen/navigation.mjs` aus dem Seitenmodell
erzeugt und in jede gebaute Seite eingebettet — eine Sidebar-Datei gibt es
nicht. Eine Quickstarts-Gruppe kennt das Navigationsmodell nicht, und Labels
stammen aus dem Seitentitel statt aus einer handgeschriebenen Zeile; die
Forderung nach einem Sidebar-Eintrag `[MCP-Server (Claude Code)](claude-code)`
beschreibt damit nichts, was noch existiert. `docs-site/index.html` war die
Docsify-Shell; sie wurde mit dem Generator-Umbau entfernt, und `data-brand`
kommt in der gebauten Ausgabe nirgends mehr vor — das Docs-Theme
(`scripts/docs-gen/theme.mjs`) ist markenneutral. Ersetzt durch die neue
Anforderung „Docs-Navigations-Integrität und Quickstart-Auslieferung".

## ADDED Requirements

### Requirement: Docs-Navigations-Integrität und Quickstart-Auslieferung

The system SHALL ensure that every relative page link emitted into a built docs
page resolves to an existing file under `k3d/docs-content-built/`, and that the
three quickstart pages are shipped.

This is the surviving intent of the retired sidebar-integrity requirement: no
dead link in the generated navigation. It is asserted against the build output
rather than against a source file, because the navigation no longer has a
source file.

#### Scenario: Kein toter Link in einer gebauten Seite

- **GIVEN** eine gebaute Seite unter `k3d/docs-content-built/` enthält Links der
  Form `href="./<name>.html"`
- **WHEN** jedes Ziel gegen das Dateisystem aufgelöst wird
- **THEN** existiert jede Zieldatei — andernfalls schlägt der Guard fehl und
  nennt die toten Ziele

#### Scenario: Die Navigation liefert überhaupt Ziele

- **GIVEN** der Guard extrahiert die relativen Links einer gebauten Seite
- **WHEN** deren Anzahl gemessen wird
- **THEN** ist sie größer als fünf, bevor die Auflösung geprüft wird — eine
  leere Trefferliste darf nicht als „keine toten Links" durchgehen

#### Scenario: Alle drei Quickstart-Seiten werden ausgeliefert

- **GIVEN** der Docs-Build ist gelaufen
- **WHEN** `k3d/docs-content-built/quickstart-enduser.html`,
  `quickstart-admin.html` und `quickstart-dev.html` geprüft werden
- **THEN** existiert jede Datei und ist nicht leer

### Requirement: Testdateien dürfen nicht auf abgeschaltete Docs-Pfade zeigen

No BATS file under `tests/` SHALL reference the retired docsify paths — the
`k3d/docs-content` directory or the `docs-site` shell HTML. A guard that points
at a path which no longer exists does not fail loudly; its `grep … || true`
constructions collapse to an empty result set and the assertion passes
vacuously, which is worse than having no guard at all because it reports
coverage that does not exist.

#### Scenario: Ein Test referenziert einen abgeschalteten Docs-Pfad

- **GIVEN** eine Datei `tests/**/*.bats` enthält einen der beiden toten Pfade
- **WHEN** der Konventions-Guard läuft
- **THEN** schlägt er fehl und nennt die Datei

#### Scenario: Der Konventions-Guard scannt einen nicht-leeren Korpus

- **GIVEN** der Guard durchsucht `tests/` nach `*.bats`-Dateien
- **WHEN** die Anzahl der Dateien mit einem `@test`-Block gemessen wird
- **THEN** ist sie größer als null, bevor die Negativ-Aussage ausgewertet wird
