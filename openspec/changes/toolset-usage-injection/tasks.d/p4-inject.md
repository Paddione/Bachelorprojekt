# p4 inject — Injektionspfad und Karte

**Besitzt ausschließlich:** `scripts/toolset-context.sh` (neu),
`scripts/toolset/emit-map.mjs`, `docs/agent-guide/maps/toolset-map.md` (generiert)

**Kontrakt:** CONTRACT.md §2 (Rollen), §3 (Exit-Codes und Ausgabeformat).

## File Structure

| Datei | Ist | Budget |
| --- | --- | --- |
| `scripts/toolset-context.sh` | neu | 800 (`.sh`-Limit, `gates.yaml` s1.limits) |
| `scripts/toolset/emit-map.mjs` | 28 | 800 (`.mjs`-Limit) |
| `docs/agent-guide/maps/toolset-map.md` | 65 | — (generiert, `docs/` außerhalb der Scan-Universe) |

`scripts/toolset-context.sh` ist eine neue Datei unter S1-Gate. Geschätzter Umfang 120–160
Zeilen — weit unter 800. `emit-map.mjs` wächst um geschätzt +40 Zeilen.

## Aufgaben

- [ ] **`scripts/toolset-context.sh` anlegen.** Aufbau bewusst parallel zu
      `scripts/plan-context.sh`, damit ein Dispatch beide mit derselben Rollen-Variable aufrufen
      kann: `set -euo pipefail`, Rolle als erstes Positionsargument, Ausgabe als Markdown-Block
      auf stdout ohne umschließende `<toolset>`-Tags (die setzt der Aufrufer, exakt wie bei
      `<active-plans>`).

- [ ] **Rollenvalidierung — fail-closed.** Die sieben Rollennamen plus `all` als Allowlist. Eine
      unbekannte Rolle beendet das Skript mit Exit ≠ 0 und einer stderr-Meldung, die die gültigen
      Rollen aufzählt.

      Das weicht bewusst von `plan-context.sh:52-55` ab, das in diesem Fall `__ALL__` zurückgibt
      und nur `WARN: unknown role` schreibt — der Rollenfilter wirkt dort dann gar nicht
      (T002322, in CLAUDE.md dokumentiert). Für Pläne ist das lästig; für einen Werkzeug-Block
      wäre es schädlich, weil eine vertippte Rolle das vollständige Arsenal in jeden Prompt
      injizierte und damit genau den Kontext-Bloat erzeugte, gegen den kuriert wird. Ein
      Kommentar im Skript hält diese Abweichung samt Begründung fest, damit sie später nicht
      „vereinheitlicht" wird.

- [ ] **Registry lesen und filtern.** `docs/agent-guide/registry/capabilities.yaml` parsen.
      Aufgenommen wird eine Instanz, wenn ihr `state` **nicht** `suppressed` ist **und** ihre
      `roles`-Liste die angefragte Rolle oder `all` enthält. Eine Instanz ohne `roles` erscheint
      nicht — sie ist unkuriert und hat in einem Prompt nichts verloren.

      Zum Parsen `node -e` mit `js-yaml` verwenden (im Repo vorhanden, von allen
      `scripts/toolset/*.mjs` genutzt) statt YAML in Bash zu zerlegen. Ein bash-eigener
      YAML-Parser bricht an der ersten mehrzeiligen Zeichenkette und ist hier nichts als ein
      künftiger Bug.

- [ ] **Ausgabeformat gemäß CONTRACT §3.** Überschrift mit der Rolle, dann je Instanz ein
      Abschnitt mit Capability, Instanz-Id, optionalem Tier-Suffix und den gesetzten Feldern als
      `**Wann:**` / `**Nicht:**` / `**Fallback:**` / `**Tiefe:**`. Nicht gesetzte Felder erzeugen
      **keine** leere Zeile — ein Prompt-Block ist Kontextbudget, und leere Rubriken kosten
      Tokens ohne Aussage.

- [ ] **Leere Ergebnismenge ist kein Fehler.** Führt keine Instanz die angefragte (gültige) Rolle,
      gibt das Skript nichts aus und endet mit Exit 0 — analog zu `plan-context.sh`, dessen
      Aufrufer-Idiom `[ -n "$context" ] && prompt=…` genau diesen Fall abfängt.

- [ ] **`--json`-Modus.** Zusätzlich zum Markdown-Block ein maschinenlesbares Format für
      `toolset-curate` und künftige Automatisierung. Der Modus gibt dasselbe gefilterte Set als
      JSON-Array aus.

- [ ] **`emit-map.mjs` um die Nutzungsfelder erweitern.** Die generierte
      `docs/agent-guide/maps/toolset-map.md` zeigt heute nur `Status` und `reason`. Ergänzen:
      `use_when`, `avoid_when`, `fallback`, `roles`, `tier`, `deep_ref` je Instanz sowie einen
      Abschnitt „Residuale Mehrdeutigkeiten", der `unreviewed`-Instanzen und `suppressed`
      Instanzen nicht durchsetzbarer Kinds auflistet — letzteres verlangt der SSOT-Spec
      („SHALL be listed in the generated map as a residual ambiguity").

- [ ] **DO-NOT-EDIT-Kopfzeile.** Die generierte Karte bekommt denselben Kopf, den
      `docs/agent-guide/maps/tools-map.md` trägt
      (`<!-- DO NOT EDIT — generated by … ; edit the registry -->`). Die Datei hat ihn heute
      nicht, obwohl sie generiert wird — eine Handänderung daran ginge beim nächsten Lauf
      wortlos verloren.

- [ ] **Karte neu erzeugen.** `node scripts/toolset/emit-map.mjs` laufen lassen und das Ergebnis
      mitcommitten, damit die committete Karte zur Registry passt.

- [ ] **Selbstprüfung.**

```bash
bash scripts/toolset-context.sh bachelorprojekt-db; echo "exit=$?"   # erwartet: exit=0, DB-Werkzeuge
bash scripts/toolset-context.sh db; echo "exit=$?"                   # erwartet: exit!=0 (Kurzform)
bash scripts/toolset-context.sh orchestrator --json | node -e "JSON.parse(require('fs').readFileSync(0,'utf8'))"
```
