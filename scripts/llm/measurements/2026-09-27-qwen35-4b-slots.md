# Qwen3.5-4B-MTP: Slots auf der RTX 3060 Ti (gemessen 2026-09-26, T900504 p4)

Frage: Bringt der 4B-Worker des plan-runners mit mehreren Slots mehr Gesamtdurchsatz, ohne dass
je Slot weniger als 32k Kontext bleibt und ohne die 3060 Ti ueber 7.600 MiB zu fuellen (der Desktop
haengt an dieser Karte, belegt ohne Modell bereits 1.465 MiB)?

Modell `Qwen3.5-4B-UD-Q4_K_XL.gguf`, llama.cpp `~/opt/llama-current` (Build e85e15c),
`--spec-type draft-mtp --spec-draft-n-max 4 -fit off -ngl 999 -fa on`, Q4 fuer Target- und Draft-KV.
Messung mit `par-streams.mjs` (N gleichzeitige Stroeme, je 400 Token, Thinking aus; Gesamtdurchsatz =
Tokens / Wanduhr) und einem Prompt nahe dem Kontextende (Spill-Erkennung).

## Ergebnis

| Konfiguration | VRAM | Kontext je Slot bei Vollbelegung | 1 Strom | 2 Stroeme | 3 Stroeme | 4 Stroeme |
|---|---|---|---|---|---|---|
| `-np 1 -c 131072` (bisher) | 7.310 MiB | 131.072 | 101 t/s | - | - | - |
| `-np 2 -kvu -c 98304` | 7.048 MiB | 49.152 | 97 t/s | 109 t/s | - | - |
| `-np 2 -kvu -c 131072` | 7.191 MiB | 65.536 | 93 t/s | 124 t/s (+23 %) | - | - |
| **`-np 3 -kvu -c 98304`** | **6.933 MiB** | **32.768** | 107 t/s | 118 t/s | **162 t/s (+60 %)** | - |
| `-np 4 -kvu -c 65536` | 7.157 MiB | 16.384 | 91 t/s | 126 t/s | 145 t/s | 160 t/s |
| `-np 4 -kvu -c 131072` | 7.645 MiB | 32.768 | ueber 7.600 MiB, nicht gemessen | | | |

Langer Prompt mit `-np 3 -kvu -c 98304`: 88.486 Token, Prefill 1.653 t/s, Decode 80,2 t/s, Needle
gefunden, 6.855 MiB — kein Spill.

## Entscheidung (p4 Task 4.2)

Kriterien: Gesamtdurchsatz +25 % und je Slot mindestens 32k Kontext, unter 7.600 MiB.

- `-np 3 -kvu -c 98304` erfuellt alle: +60 %, 32k je Slot, 6.933 MiB → neuer Default in
  `scripts/llm/qwen35-mtp.service`, `--4b-slots` Default 3.
- `-np 2 -kvu -c 131072` verfehlt die 25 % knapp (+23 %).
- `-np 4` erreicht 32k je Slot nur mit 131k Pool, der die VRAM-Grenze reisst; mit 65k Pool bleiben 16k je Slot.

Mit `-kvu` ist der Pool geteilt: ein einzelner Request darf die vollen 98.304 Token nutzen, solange
die anderen Slots frei sind. Das opencode-Limit fuer `llamacpp-qwen35` steht deshalb auf 98304.

Nebenbefund: `-kvu` teilt nur Speicher, keine Inhalte. Ein identischer System-Prompt (6.842 Token)
wird nur vom Slot wiederverwendet, der ihn schon hatte (`prompt_n` 4 bzw. 22 statt 6.842).
